# Self-Fix Review

Present the pending Gardener proposals in `~/.claude/dockwright/gardener/proposals/pending/` and act on whichever the user accepts. The sitting is PROPOSALS-ONLY: raw selffix findings (`~/.claude/dockwright/selffix/findings/`) are the GARDENER's input — the digest lane clusters them into proposals, and this sitting never re-does that digestion by hand.

> Throughout, `<dockwright_repo>` means the dockwright checkout path, configured as `[paths] dockwright_repo` in dockwright.toml. Where a target is cp-deployed, its canon lives under `<dockwright_repo>/deploy/`.

## When to Use
- User asks to "review selffix", "review gardener proposals", "hold a review sitting".
- Pending proposals have accumulated — the statusline 🌱 badge counts `proposals/pending/*.md`.
- After a Gardener digest run lands new proposals.

If `proposals/pending/` is empty: print "no pending proposals", run **The remainder** step at the end of this file (human-label grep included), and stop. Never fall back to hand-digesting raw findings.

## Marked-reviewed contract

A findings file `<sessionId>.md` is considered **reviewed** when a sibling zero-byte file `<sessionId>.reviewed` exists next to it. The markers are written by `gardener_postrun.py decide` (batch-marking a decided proposal's members) — the sitting hand-marks only on an explicit user dismissal of a named finding (rare; record it in the wrap-up). Never delete or rename the original `.md` — the audit trail stays; reviewed findings are age-pruned by the selffix trigger after 14 days.

## The sitting

0. **Back-pressure banner.** Read the last `backpressure` event from `~/.claude/dockwright/gardener/ledger.jsonl`, e.g.:
   ```bash
   python3 -c "
   import json, os
   path = os.path.expanduser('~/.claude/dockwright/gardener/ledger.jsonl')
   bp = []
   try:
       with open(path) as fh:
           for line in fh:
               line = line.strip()
               if not line:
                   continue
               try:
                   rec = json.loads(line)
               except ValueError:
                   continue
               if rec.get('type') == 'backpressure' and rec.get('lane') == 'digest':
                   bp.append(rec)
   except OSError:
       pass
   print(bp[-1] if bp else 'none')
   "
   ```
   A `none` result (no event yet, or no ledger) means no banner — proceed silently. If it carries `violation: true`, open the sitting with this banner BEFORE any proposal: "⚠️ Back-pressure violation: the last <streak> proposal-bearing digest runs carried zero negative-byte proposals — the always-on corpus only grew. Expect eviction proposals below; if none are present, ask the digest lane why (its Notes must carry `no negative-byte proposal this run: <why>`)."
1. **Establish CURRENCY first, then read.** Before anything else in this step, `git -C <root> fetch origin` for every root `currency` names in its header (one or two: `~/.claude` plus `[paths] dockwright_repo` when set) — never hand-derive the roots from `targets:`. Then run `python3 ~/.claude/scripts/gardener_apply.py currency` ONCE for the whole queue. It prints, per proposal, one of `fresh` / `STALE` / `unknown` / `n/a`, the key it used per target, and for every moved target the exact re-derivation command. Its header also prints each root's last-fetch time — for a root WITH a remote, a last-fetch older than a proposal's drafting makes that proposal's targets come back `unknown` by construction (a root with no remote at all has nothing to be stale against, so the gate does not apply to it). ⚠️ The gate reads `FETCH_HEAD`, which ANY remote's fetch bumps — it proves *a* fetch happened, not that `origin` was refreshed; that is why step 1 mandates `git fetch origin` per root rather than trusting the timestamp. A NON-ZERO exit means the probe did NOT run: read that as "currency unknown", never as "all fresh". Carry each verdict into that proposal's presented subsection (step 2), and honour step 3 before presenting a `STALE` or `unknown` one.

   **Read every pending proposal** (parallel Reads). Each carries YAML frontmatter (`id`, `cluster`, `lane`, `members`, `targets`, `kind`, `always_on_bytes`, `flow_cost`, `expectation`, `check_window_days`, `revert`) + Evidence / Diff / Rationale sections. The **`lane` field is the SOURCE** and BOTH lanes share this one queue, so it must be made explicit at review: `frontier` = the external frontier-research loop; `digest` = the internal selffix/ops-evidence Gardener (our retros). A proposal missing `lane` is legacy → treat as `digest` (Selffix). Additionally run `python3 ~/.claude/scripts/gardener_apply.py check --proposal <path>` per proposal (cheap, read-only) and carry an `applies cleanly: yes/no` line into each presented subsection — the check prints a CLASS: `clean` / `reanchorable` (both apply — reanchorable means the diff's hand-written hunk headers are wrong but the content anchors uniquely; the actuator re-anchors it) / `drifted` (target really changed — re-draft) / `ambiguous` (context matches twice — hand-apply or re-draft) / `missing-file` (target path moved) / `malformed` (diff unparseable — re-draft) / `out-of-scope` (diff names a path outside declared targets/allowed roots — re-draft). Carry the class into each presented subsection; only `drifted`/`ambiguous`/`missing-file`/`malformed` change the decision calculus. Exception: a `kind: corpus-retire` proposal ships a PROSE `## Diff` (no ```diff fence) by design — skip the apply-check for it, like build-briefs.

   ⛔ **`check` and `currency` answer DIFFERENT questions and neither substitutes for the other.** `check` says whether the diff's lines still apply; `currency` says whether the target moved at all. Measured 2026-08-21 on a 15-proposal queue: the one proposal whose rationale was genuinely dead was a prose build-brief `check` does not run on, while two proposals `check` called `clean` had moved targets. Every proposal gets a `currency` verdict — build-briefs and `corpus-retire` included, since `currency` reads only frontmatter and never parses the diff.
2. **Present each as a `###` subsection with handle G1, G2, …**, the header PREFIXED with the source badge so the lane is unmistakable at a glance — `### 🔭 G1. <cluster>` for `lane: frontier`, `### 🔧 G2. <cluster>` for `lane: digest` (selffix). Bold-labeled paragraphs separated by blank lines, findings separated by `---` horizontal rules (bullet lists collapse adjacent items in CommonMark; subsections + horizontal rules don't): **Source.** `🔭 Frontier` (external research) or `🔧 Selffix` (internal retro/ops evidence) · **Cluster.** name + member count · **Evidence.** 1–2 sentence summary · **Change.** target file(s) + one-line diff summary + `always_on_bytes` cost + the `flow_cost` line (a proposal drafted before PRD A7 carries none — print `flow_cost: (legacy — not assessed)`, and drop this parenthesis once no pre-A7 proposal remains pending) — for `corpus-retire`: "no artifact change; retires <n> members" · **Currency.** the `currency` verdict. ⛔ **The rule is PER TARGET, not per proposal, on ALL FOUR classes** — a proposal's targets routinely disagree, so one sentence covering the proposal certifies things it never measured. Name every declared target, its own row's class, and the key that row used: `fresh` → "no commit reached `<ref>` touching `<file>` since `<its key>`"; `STALE` → "`<file>` moved +<n> since `<its key>`; re-derived — <holds / superseded>"; `unknown` → "`<file>`: currency NOT established — <the row's reason>; treated as STALE"; `n/a` → "`<file>`: nothing to measure — it does not exist yet, and this proposal is the one that creates it (`new-asset`) or briefs it into being (`build-brief`)". ⛔ No wording may say "this proposal is still valid": the probe measures drift in the DECLARED targets, which is a proxy — it is blind to a rationale killed by a change to a file the proposal does not declare. ⚠️ A row on `key=since` is the weak key — it filters by committer DATE, so it cannot see a backdated commit that arrived on the ref after drafting; say so in that row's sentence. · **Expectation.** the falsifiable sentence. When ≥1 of each lane is present, keep frontier and selffix proposals in clearly separate visual groups (e.g. a `🔭 Frontier proposals` / `🔧 Selffix proposals` divider) so the user is never guessing which is which.
3. **A `STALE` or `unknown` proposal is RE-DERIVED before it is presented.** `fresh` and `n/a` are not — their verdict line is the whole actualization. For a `STALE` row, run the re-derivation command `currency` printed beneath it; ⛔ do not hand-assemble `<base_rev>..origin/main`, because `base_rev` names ONE root and on a multi-root proposal that form is `fatal: bad revision`. An `unknown` row prints NO such command — there is nothing to diff — so act on the reason its row states instead: fetch and re-run, or go look at why the target is absent from the ref. Read the target as it now stands, then answer one question: **do the proposal's Evidence and Rationale still hold against the current text?** Two outcomes only. **They hold** → say so in the `Currency.` label and carry the proposal on normally. **They do not** — the problem is already fixed, the target now contradicts the proposal, or the rationale quotes text that is gone → present it as `STALE — superseded`, recommend defer, and do NOT accept it; deferring leaves it in `pending/` and the next digest re-drafts it against the moved target. ⛔ Never hand-edit the diff to fit the moved target — that is the model edit T11 bans.

4. **Annotate via plannotator (optional).** For a longer queue (≈6+ proposals), write the same digest you presented in chat to a temp file and let the user annotate it inline: `DIGEST="$(mktemp -d)/digest.md"`, Write the digest markdown there, then with the Bash tool run `plannotator annotate "$DIGEST"` with `run_in_background: true`. It opens the file in the browser annotation UI, blocks until the user submits, then prints the structured annotations to stdout (delivered when the background task completes). The user marks each proposal ✓ / ✗ / ? with freeform notes — cheaper than a chat round-trip per proposal. Keep the temp file OUTSIDE `~/.claude/dockwright/selffix/findings/`: `gardener_gate.py` counts that dir and the digest skill's Step 2.1 enumerates it, so an artifact written there would feed the pipeline its own presentation. **Why the CLI + an explicit file, NOT the `plannotator-last` Skill:** `plannotator annotate-last` self-selects "the last rendered assistant message" from the transcript, which has opened the wrong message even when the digest was the immediately preceding standalone message; targeting an explicit file is deterministic. (The `/plannotator-annotate` slash command is `disable-model-invocation`, so the Skill tool can't reach it — the Bash binary is the supported path; `run_in_background: true` avoids the Bash 600 s timeout while the user reviews at their own pace.) Treat returned annotations as authoritative for step 5; fall back to a single `AskUserQuestion` only for proposals the annotations left unresolved.
5. **Per decision, the bookkeeping is ONE command** (never hand-roll the moves/markers):
   - ACCEPT — the diff is applied by CODE, not by hand (T11); never re-make the edit with Edit/Write:
     1. For `kind: new-asset`, sanity-check the destination home first (rule vs skill vs agent-file vs memory — cheapest correct home, matching neighbouring assets). **If the target is cp-deployed** — `setup.sh` copies it into `~/.claude` from the canon (usually same relpath, sometimes RENAMED, e.g. `~/.claude/dockwright/presets/X` ← `deploy/presets/X`) — the proposal's `targets:`/diff must point at the CANON SOURCE under `<dockwright_repo>/deploy/`; if it points at the `~/.claude` copy, defer for re-draft (or hand-redirect the diff header with explicit user sign-off).
     2. `python3 ~/.claude/scripts/gardener_apply.py apply --proposal <path>` — parses the `## Diff`, classifies (strict `git apply --check` first, content-anchored re-anchor as fallback), applies all-or-nothing with snapshot rollback and prints the git-generated diff of what actually changed. On failure the error names the class (`drifted`/`ambiguous`/`missing-file`/`malformed`/`out-of-scope`/`canon-gate`): surface it; `canon-gate` means the post-write gate refused — for a test-bearing target repo the apply runs that repo's FULL suite (~3 min) and refuses+rolls back if it goes red (pre-existing red vs apply-broke is stated in the message); everything was restored, canon untouched. the human picks defer (next digest re-drafts) / decline / explicitly-sanctioned manual edit. Never silently fall back to a model edit.
     3. **Canon target only:** run `./setup.sh` from the main dockwright clone now — the gate evaluates the LIVE `~/.claude`, and an undeployed canon diff would gate the pre-change stack (false pass). Precondition: the rest of the main-clone tree is clean (`git status`) — setup.sh deploys the WHOLE tree, and the apply script dirty-checks only the targets; unrelated uncommitted state would ride along into `~/.claude`. setup.sh refuses (exit 4) over a live fleet (`~/.claude/dockwright/active/*.json`) — this sitting's own session included; this deploy is the deliberate-live-deploy case the override exists for. Check `ls ~/.claude/dockwright/active/`: if nothing beyond this sitting (and its manager) is mid-flight, run `DOCKWRIGHT_SETUP_FORCE=1 ./setup.sh`; with unrelated in-flight workers, HOLD the apply until the fleet is quiet — never blind-force, and never proceed to the eval gate with an undeployed canon diff (false pass).
     4. `python3 ~/.claude/scripts/gardener_eval_gate.py --proposal <path>` with `run_in_background: true`. The gate ALWAYS prints a per-file coverage table first (each target → matched suite(s) or UNMAPPED). WAIT for the verdict before deciding this proposal — and while any gate runs, do NOT apply other proposals (any live-stack edit mid-suite corrupts the verdict's attribution; declines/defers/presentation may continue). Exit codes: **0 = PASS** (or an explicit `--allow-unmapped` skip) → next step. **1 = FAIL** (behavioral) → `python3 ~/.claude/scripts/gardener_apply.py revert --proposal <path>` (canon: re-run `./setup.sh` after the revert — same force discipline as step 3), surface the failing cases, human decides decline/defer. **2 = infra-suspect** (outage/errored samples, NOT behavioral) — surface it; don't treat as a failed proposal, but it STILL blocks the decide: keep the diff applied and re-run the gate after the outage, or revert + defer — never commit+decide on an infra-suspect verdict. **4 = NOTHING mapped** (0 of N touched files routed to a mapped suite — NOT a silent pass; a `skipped-unmapped` ledger event is written): read the coverage table. `--allow-unmapped` (which downgrades exit 4 → 0) is legitimate ONLY after confirming the canon gate inside `apply` already covered those touched files — then re-run with `--allow-unmapped` for the auditable skip and continue; otherwise it is a real coverage gap — surface it and defer rather than proceed. **5 = mapped suites PASSED but ≥1 target UNMAPPED** (`passed-partial` — the mapped subset's green does NOT cover the rest) — read the coverage table; treat the unmapped remainder exactly like exit 4: a legitimate `--allow-unmapped` re-run (which downgrades 5 → 0 the same auditable way) ONLY after confirming the canon gate covered those files; otherwise surface-and-defer.
     5. Commit the target repo(s) yourself (`git add <targets> && git commit -m "gardener: apply <proposal-id>"`) — don't wait for the `~/.claude` auto-commit Stop hook: it only fires at end-of-turn with a generic message, and the next step needs the SHA now, attributed to this proposal. For the dockwright repo: commit + push per its conventions.
     6. `python3 ~/.claude/scripts/gardener_postrun.py decide --proposal <path> --kind accept --reason "<optional note>" --applied-rev <root>=<sha>` (repeat `--applied-rev` per committed root).
   - ACCEPT of a `kind: corpus-retire` proposal (prose diff, nothing to patch — its `targets:` names the findings dir it retires from; drafted by the digest to retire never-clustered parked findings as spent evidence): skip sub-steps 1–5 entirely — nothing to apply, no `setup.sh`, no eval gate, no commit — and run sub-step 6 directly WITHOUT `--applied-rev`. The decide batch-marks every member finding `.reviewed`; the selffix trigger prunes them after 14 days.
   - DECLINE: ask the user for a one-line reason (required — it's what stops the cluster from re-surfacing absent new members), then:
     `python3 ~/.claude/scripts/gardener_postrun.py decide --proposal <path> --kind decline --reason "<their reason>"`
   The command moves the proposal to `accepted/`/`declined/`, appends the ledger `decision` event, and **batch-marks every member finding `.reviewed`** — those findings leave the unreviewed corpus automatically (exception: a `corpus-retire` DECLINE marks nothing — declining retirement keeps the members in the corpus).
6. **Don't re-litigate declined clusters.** Anything under `proposals/declined/` stays decided; the digest pipeline re-surfaces a cluster only when strictly-new members appear.
7. Deferring a proposal (no decision) is fine — it just stays in `pending/` for the next sitting.

## The remainder — raw findings route to the Gardener, not to this sitting

After the proposal decisions (and on the empty-queue path), enumerate what is still unreviewed:

```bash
find ~/.claude/dockwright/selffix/findings -maxdepth 1 -name '*.md' | while read f; do
  [ -f "${f%.md}.reviewed" ] || echo "$f"
done
```

1. **Human labels first.** Grep the remainder for `**Source**: manual`, the literal `🚩 [MANUAL]` heading prefix, `⚖️ [CORRECTION]`, and `**Source**: engineer-correction` — the digest skill's Step 2–3 detection recipe; never a bare command-name substring (`fix` / `dockwright-fix` or any deprecated alias), which false-positives on retros that record the marker's *absence* in prose. Surface every hit explicitly — the verbatim flagged text + its sid — so the user can direct it: leave parked (the next digest may cluster it or draft its proposal), kick a digest run now (item 3), or explicitly dismiss it — on an explicit dismissal of a named finding, `touch` its `.reviewed` marker in that turn and record it in the wrap-up (the one hand-marking exception: a recorded human decision, not model auto-marking). A human-flagged finding the digest why-notted out of a proposal must never dissolve into a count; this grep is its surviving decision surface.
2. **Everything else is ONE line**: `<n> findings unreviewed — Gardener input (fresh feed + parked singletons + members of still-pending proposals); nothing to hand-review here.` They terminate through the pipeline, not through this sitting: a member of a still-pending proposal is batch-marked when that proposal is decided; everything else is re-read by every digest run (incremental runs fold in the non-member remainder — see the digest skill's Args) and either clusters into a future proposal or, at 30 days parked, enters a `corpus-retire` proposal. No badge counts raw findings (the statusline counts pending proposals), so a parked remainder lights nothing.
3. To force an immediate re-cluster (rare): `python3 ~/.claude/scripts/gardener_gate.py --force` spawns a visible digest run.

## Output Format

Final wrap-up after the decisions:
```
Accepted: <proposal ids → applied targets, or "retired <n> members" for corpus-retire>
Declined: <proposal ids + one-line reasons>
Deferred: <proposal ids>
Remainder: <n> unreviewed findings (Gardener corpus); 🚩/⚖️ surfaced: <list or none>; hand-dismissed: <list or none>
```

## Common Pitfalls

- **Never hand-digest raw findings or hand-apply a "quick fix" from one.** Findings are the Gardener's input; anything in the findings dir that needs action reaches this sitting as a proposal (or as a 🚩 remainder hit for the user to direct).
- **Never `touch` `.reviewed` outside an explicit user dismissal of a named finding.** `gardener_postrun.py decide` is the writer; a silently hand-marked finding vanishes from the Gardener's corpus with no decision recorded.
- **Don't rename or delete finding `.md` files.** The `.reviewed` sibling is the only marker; the originals stay so the user can re-read later.
- **Don't apply other proposals while an eval gate runs** — a live-stack edit mid-suite corrupts the verdict's attribution; declines/defers/presentation may continue.
- **Don't re-litigate declined clusters.** Deciding them again without strictly-new members burns the sitting's time and contradicts the ledger.
- **Don't dispatch a subagent for the decision/apply steps** — the parent session holds the conversation state and the user's decisions; a subagent loses that thread.
- **A clean `check` is not a currency verdict, and a `fresh` currency verdict is not "it will apply".** They read different trees: `currency` reads the remote default branch, `apply` patches the working tree, and the eval gate reads the DEPLOYED `~/.claude` copy — `setup.sh` deploys by `rsync -a`, a real copy, so the deployed one genuinely can lag. Measured 2026-08-21 on this very skill file: the remote default branch differed from the local canon by 4 undeployed `deploy/` commits, while the deployed copy was byte-identical to the local canon. A proposal can be `fresh` and refuse to apply, or `STALE` and apply perfectly clean.
- **Never key staleness on the proposal FILENAME timestamp.** It is the run/finding id, not the drafting moment. A redrafted proposal carries a filename up to two weeks older than its own diff — `20260803T103356Z-20730-5` says so in its own `redraft_note` — so the filename key flags commits the drafter had already read. `base_rev` is re-stamped on redraft; it is the key, and `currency` already applies it.
- **Don't accept a `STALE — superseded` proposal to save the work.** Defer costs one line and the next digest re-drafts it; accepting ships a change whose reason has died. The measured case would have built a mutation harness its own target rule had just forbidden.
