# /manager

You are entering **manager mode**. Optional `$ARGUMENTS` selects a domain (default `general`); domains scope memory pools.

Do the following in order:

1. Parse `$ARGUMENTS` for a single token — that's `<domain>`. If empty, use `general`.
2. Resolve `<your sid>` from the session id in system context / `$CLAUDE_CODE_SESSION_ID` (managers run under Claude Code). If you need to inspect it from shell, run `printenv CLAUDE_CODE_SESSION_ID`. Do not invent or synthesize a sid.
3. Call `dockwright` MCP tool `become_manager` with `claude_sid=<your sid>`, session_id if available, and `domain=<domain>`. It returns `{ok, name, domain, runtime}` (`runtime` is always `claude`). The `name` is your auto-rolled funny `<adjective>-<mythical-creature>` handle, unique across all active records. Save it for use in subsequent tool calls (most tools take an optional `manager_sid=<your sid>`). It also paints your tmux tab (name · domain) and runs preflight cleanup server-side — surface the returned `preflight` line to the user if non-empty (older orchestrator builds may omit the field; then skip silently).
3b. Model check (a manager's model is the `manager_model` its install resolves: `[spawn] manager_model` in dockwright.toml, else the release default; a `/manager` typed inside an existing session keeps that session's model): run `dockwright model manager '<id>'`, with `<id>` the exact model id your system prompt states, in single quotes. It prints `same <resolved id>` or `differs <resolved id>`, `<resolved id>` being the concrete id the lane specs. Trust that word over your own reading of the two ids: Claude Code leaves a no-op `[1m]` out of the id it states. On `differs`, tell the user: "This manager is running on <id>; the manager lane is specced for <resolved id> — consider `/model <resolved id>` or relaunching." ⛔ Never put a `@` token in that sentence: the user types what you give them, and the CLI answers `unrecognized_model` for a token. If `dockwright model manager` exits non-zero, tell the user its stderr instead. Also check the effort: the manager lane is specced for `[spawn] manager_effort` in dockwright.toml, else `medium` — if the statusline shows anything else, say so and suggest relaunching. Then continue — both are warnings, not gates.
4. Call `dockwright` MCP tool `attach_existing(manager_sid=<your sid>)`. If it errors, the orchestrator MCP isn't installed — surface the error and stop.
5. Read the result. Tell the user: "Manager mode active as **<name>** (domain: <domain>). Re-attached to N workers. M questions pending."
6. If your system prompt already contains the line `<!-- dockwright-role: Manager launch=manager -->`, your manager definition is loaded: skip this Read. Otherwise load the manager definition from `~/.claude/roles/Manager/role.manager.md` when that file exists, else from `~/.claude/agents/manager.md`. **This file (~46 KB / 388 lines shipped; an operator overlay adds to that) can with an overlay exceed the ~25k-token single-Read cap, so one `Read` silently truncates it — the later sections just never arrive, with no error.** You MUST page it to EOF before acting: the total line count N is the `AGENT_LINES <N>` line printed by `dockwright boot-brief` (step 6b below). `Read` the file in windows of ≤200 lines (`offset=1`, then `offset=201`, then `offset=401`, … each with `limit=200`) until a window reaches line N. **Do not act on a partial read** — if the last line you have read is below N, page again. Only once the whole file is in context, follow its operating principles for the rest of this session.
6b. Load recent manager memory + the manager notebook for your domain: run `dockwright boot-brief --domain <domain>` (substitute `<domain>` with the domain you registered as). It prints AGENT_LINES plus **paths only** — `Read` each printed `MEMORY <path>` and the `NOTEBOOK <path>` with the Read tool (Read paginates, so nothing is dropped). It prints pointers rather than file contents because the memory distills + the notebook can overflow the Bash inline-output cap, leaving only a ~2 KB preview in context — silently dropping memory and notebook content (this is why an old inline-`cat` boot could falsely report the notebook empty). The `MEMORY` pointers are the newest 3 files by mtime among those from the last 7 days (a busy week can produce 15+ files; the cap keeps boot cost bounded). If any printed, these are distilled summaries of recent manager sessions in this domain (your peers + predecessors) — fold them into your working context. Surface "Loaded N memory files (newest 3 within last 7 days)." in your startup brief. If no `MEMORY` line printed, skip silently. The `NOTEBOOK` pointer is your domain's current-state agenda (`~/.claude/dockwright/notebook/<domain>.md` — see `~/.claude/agents/manager.md` § Manager notebook): if it printed, count its unresolved entries — every `## ` header not marked `## [x]`, the same selector the agent file's § Manager notebook names, because a ruling entry carries no checkbox and `## [ ]` silently misses it, evaluate which look ripe (date conditions by inspection; others via the entry's named `check:` command — one cheap call each), and add "N unarchived entries, M look ripe" to the startup brief, flagging any entry past its `review-by` for triage. ⛔ Naming a specific entry in the brief is a RELAY, and the agent file's § Manager notebook gate binds it: run that entry's `check:` first. A brief that only COUNTS entries asserts nothing and needs no check. If boot-brief printed a `NOTEBOOK_WARN` line, archive resolved entries per the agent file. If no `NOTEBOOK` line printed, skip silently — no mention in the brief.
7. Arm the four lane monitors. Invoke `Skill(dockwright:arm-lanes)`. The dockwright plugin then starts the four lane monitors (`dockwright monitor-loop questions|done|turn-ends|stale`); a lane already armed in this CLI process is skipped, so the call is idempotent. Wait 10 s (`sleep 10`) before the first `dockwright lanes` — arming lands about 5 s after the skill call and a lane needs one more scan to heartbeat, so an immediate read shows `NEVER-ARMED` or `ARMED-UNRESOLVED` rows on a healthy install; if any row reads `NEVER-ARMED` or `ARMED-UNRESOLVED`, run `dockwright lanes` once more after another 10 s before you follow its recovery line. For any row that is still not `OK`, do what its recovery line says; the fallback it may name is a degraded mode — say so in your brief. Lane output: `dockwright-orchestrator-guide` § Lane monitors.
8. From this point on, the user is in manager mode. Confirm with: "Manager active. Tell me what to spawn."
